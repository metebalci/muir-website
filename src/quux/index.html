THE MACHINES · QUUX, THE CADR EVOLVED

QUUX

QUUX is the CADR, evolved: MIT’s microinstruction and the same way of running Lisp, with the processor, its memory and its devices rebuilt where a change pays for itself.

muir-sim models it as quux, beside cadr, MIT’s machine as built; muir-fpga builds it for FPGA boards.

The processor ↓What it changesThe pipeline

QUUX keeps the CADR’s microinstruction, inside a wider one of its own, and its way of running Lisp, and changes the parts that held it back. Three projects make it: muir-sim models each change and holds it to tests; muir-sys writes the microcode and builds the Lisp system for it; muir-fpga is the machine on an FPGA board, where --machine quux chooses it. The CADR stays MIT’s machine; QUUX runs muir-sys’s microcode and system for it, the 2xxx releases.

The processor.

02 / THE MEMORY PORT AND THE REGISTER PAGE

The whole machine.

The CADR puts everything behind its bus interface: main memory, the disk and the display on the Xbus, and the keyboard, mouse, clocks and network on the Unibus through the I/O board.

QUUX’s processor has its microsecond clock inside, reaches main memory and the frame buffer on a port of its own through a cache, and its devices’ registers through its register decode, all of them on its register page; the devices move bulk data to and from memory themselves. There is no Unibus, no bus interface and no debug cable.

03 / WHAT QUUX CHANGES

Rebuilt where
it pays.

QUUX names itself in a word only it answers, its MACHINE-ID, and lists its sizes on a page of device registers, its feature page. Software reads that word first, then the page.

THE MICROINSTRUCTIONTHE CONTROL STORE

64

bits, against 48

MIT’s 48 bits keep their meaning, and 16 more give the pipeline its predictions: a conditional jump’s hint, a dispatch’s predicted target, or a PDL address field.

THE PIPELINENO DELAY LINES

4

stages, one clock each

The CADR times a microcycle with delay lines. QUUX fetches, reads, executes and writes back in four stages of one clock each, predicting each transfer and checking it a clock later.

PAGINGA TLB

232

words of virtual address space, against 224

No map: a page table in main memory, which the hardware walks when its TLB misses. Virtual addresses are 32 bits, physical 28, and a page is 1024 words.

THE PDL BUFFERTHE STACK

16K

words, against 1K

It needs QUUX’s own boot PROM, and microcode that knows the size: MIT’s 323 does not run on it.

MULTIPLY AND DIVIDEONE INSTRUCTION EACH

ALU functions 42 and 43, each bit for bit what the CADR’s step sequence gives.

CLOCKS OF ITS OWNTHE TIMERS

3

QUUX’s processor reads a microsecond clock in one microinstruction, and its register page has three interval timers. Timer 0 is the tick, the machine’s 60-cycle clock.

THE VIDEO CONTROLLERTHE DISPLAY

1920×1080

at most, one bit a pixel

A plain frame buffer and one register in place of the CADR’s TV boards. Each board’s bitstream fixes its size (the boards), and the system reads the size from the feature page at boot, so one band runs on each.

BLOCK-DISKTHE DISK

228

The CADR disk controller’s registers and command lists with the drive’s cylinders, heads and sectors taken out: numbered blocks of 1,024 bytes. It is QUUX’s only disk.

NO UNIBUSTHE I/O BOARD

0

Unibus cycles, and no I/O board

The keyboard and mouse and the interrupt and error status are on QUUX’s register page and the microsecond clock is in the processor. There is no serial port and no debug cable: the console’s registers are the host’s port alone.

THE MEMORY PORTTHE CACHE

{{quux.cache.least}}–{{quux.cache.most}}

words of cache, by board

Main memory is off the bus the CADR shares with its devices: the processor reaches it, and the frame buffer, on a port of its own through a two-way, write-through cache of 8-word lines. The CADR’s bus interface has nothing left to do, and QUUX has none.

DEVICE REGISTERSTHE REGISTER PAGE

1

page of device registers, and no bus

The processor reaches its devices’ registers through its own register decode, all of them on one register page at the end of the device window: the video controller’s, block-disk’s and the Ethernet device’s with the rest. Registers carry control and small data; bulk data moves between a device and memory by itself.

THE REAL-TIME CLOCKTHE TIME

1970

and whole seconds since, in one word

The real time as Unix seconds, an unsigned 32-bit number that lasts to 2106. It is live: the host keeps it, and the machine never sets it.

THE FILE DEVICEFILES

HOST

folders of the host, as one pathname host

QUUX reads and writes files on its host through a device of its own: commands and responses in two rings in main memory, the bytes moved by direct memory access, and the registers carrying control and the rings’ indexes.

THE ETHERNET DEVICETHE NETWORK

TCP

and IPv4, ARP and ICMP echo, in Lisp, in place of Chaosnet

The Ethernet device moves Ethernet frames by direct memory access and checks their checksums; ARP, IPv4, ICMP echo and TCP are written in Lisp, and the system’s TELNET server is reached over TCP.

A STANDARD DISKTHE DISK FILE

VHD

QUUX’s disk is a raw image or a VHD, of any size, partitioned by GPT and made and filled with standard tools. The CADR keeps MIT’s pack and label.

THE FUSED RETURNTHE MAIN LOOP

1,024

entries of a MACRO DISPATCH MEMORY

A return to the main loop goes straight to the next macroinstruction’s handler, from the MACRO DISPATCH MEMORY.

THE 40-BIT WORDTHE TAG

40

bits a word, against 32

A tag in bits 39 to 32 over a 32-bit field, through every data path and in main memory.

GENERATIONSTHE PAGE TABLE

1

A store of a pointer into the ephemeral space, of a type the pointer-type register names, sets its page’s ephemeral-reference bit in the page table. muir-sys’s generational collector reads those bits to scan only the pages that may point at young objects.

04 / HOW FAST

A clock a stage
and a cache.

The CADR takes a microcycle as a string of delay-line phases, 145 ns at its normal speed, and its memory board answers a request 458 ns later. QUUX has no delay lines: its pipeline runs at the period each board’s fit closes at, and a cache stands in front of memory.

Each board’s fit is routed and meets its period, and the board keeps the cache its block memory holds: the boards’ table gives both. A wrong prediction costs one bubble and a start that page-faults two: the pipeline, below.

05 / THE PIPELINE

Four stages,
one clock each.

Each microinstruction takes four stages of one clock each. Data moves left to right; control decisions flow back to the fetch. This is the design muir-sim’s rtl models and the FPGA core matches clock for clock.

The four stages are CS, fetch; RD, read and decide; EX, execute and check; and WB, write and start. Below the figure, six notes give what a wrong guess costs, why predictions pay, the fused dispatch D, the memory, halt and checkpoint, and the clock.

What a wrong guess costs

A wrong prediction squashes the instructions behind the delay slot and restores RD’s copies: 1 bubble. A start that page-faults squashes late: 2 bubbles.

Why predictions pay

The profile pass sets each jump’s hint and each dispatch’s predicted target from the measured majority. Measured over the workloads, the hints save 2.7% of the clocks and the predicted targets 3.8%.

D, the fused dispatch

A main-loop return can fetch the next macroinstruction and dispatch on it. Its effects wait for the fetched word and start the handler in CS one clock later (L = 1). The microcode turns it on.

Memory

Two different caches sit on the way: the TLB holds address translations (a virtual page to a physical frame), and the data cache holds memory words. Writes are posted: WB hands them to the queue and goes on. A word written is fixed when its start’s microcycle ends. A read waits only when its line has a write still on its way.

Halt and checkpoint

A halt completes the instructions in EX and WB, squashes CS and RD, and waits for the port to empty. The machine then stands between two microcycles, as the single-edge simulator would.

The clock

QUUX runs on each board at the period its fit closes at, routed and met (the boards).

07 / RUNNING IT

In software,
and in fabric.

QUUX’s released system runs in muir-sim and on FPGA boards; each page says how. Either one needs microcode and a system written for it, from muir-sys: MIT’s own will not run on it.
