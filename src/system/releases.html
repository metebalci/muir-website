MUIR-SYS · RELEASE NOTES

Releases

Every release is a whole band, built from the sources by a clean compile, a new cold load, QLD and a save. There are no patches: a release is replaced by the next one.

QUUX’s releases are numbered from 2000 and made from the repository’s main branch; the CADR’s are the 1000s, made from its cadr branch. A band runs only on the machine it is for.

01 / RELEASE · QUUX

System 2000

2026-09-29 · tag release-2000 · get it

The first release for QUUX, the CADR evolved. It runs only on QUUX, on microcode 2000 and boot PROM 2000, and was built on QUUX, every file compiled.

WHAT CHANGED

  • QUUX only. The band and the microcode check the machine at boot and stop on anything but QUUX hardware revision 11 or later. The system takes its sizes from QUUX’s feature page: the PDL buffer, the level-1 map, the video controller’s screen.
  • QUUX’s own devices, on its register page at 17777400: block-disk, whose disk is a GPT disk (a VHD on the host); a real-time clock, which a boot takes the time from; a file device, through which SYS: is on HOST, the machine’s host folder, so no file server is needed; three interval timers, the tick among them; the video controller, a one-bit frame buffer up to 1920 by 1080.
  • The boot PROM saves nothing and writes nothing to the disk, and resets the devices; the PROM and the microcode find the microcode and the band by the disk’s GPT.
  • Faster simple instructions: the microcode fills QUUX’s MACRO DISPATCH MEMORY at every start, with handlers for moves, pops, branches and three arithmetic instructions on locals and arguments.
  • Time zones by name, a tzdata zone in the site’s :TIMEZONE, and FILE dates in UTC on the wire.
  • Faults fixed in dates (1900, 2000 and after 2100; summer time; four-digit years), division by the most negative fixnum, the error table, QLD, the directory date parser and pathname matching, among others.
  • The herald names the site and the machine type; the site defines LISPM-1 to LISPM-7.

03 / RELEASE · THE CADR

System 1002

2026-09-29 · tag release-1002 · get it

The CADR’s system after System 1001: MIT’s time code made right, FILE dates in UTC on the wire, the CADR’s first changed microcode, 1000, and the faults found on the way. It runs on the CADR, not on QUUX.

TIME AND DATES

  • The site’s :TIMEZONE takes a tzdata zone name, such as "Europe/Berlin", and summer time follows that zone’s rule; the example site names Europe/Berlin. A number is a fixed offset with no summer time.
  • FILE dates on the wire are UTC, with the year in four digits; the machine still shows dates in its own local time. The band’s own FILE server sends UTC too.
  • The calendar follows the Gregorian rule: 1900, 2000 and the years from 2100 on were a day off. Encoding and parsing a date agree with decoding on summer time, and the directory date parser checks its fields.
  • The cold load records each file’s date as the server sends it, so QLD loads none of the cold load’s files a second time, nor MINI’s.

MICROCODE 1000

MIT’s 323 with three fixes, each of a fault of MIT’s:

  • dividing by the most negative fixnum no longer corrupts a result or halts the machine;
  • %DRAW-RECTANGLE reads no row below the rectangle;
  • a small-flonum overflow and %ASSURE-PDL-ROOM trap before their return, so proceeding from the trap works.

FIXED

The herald names the site, whatever it is; the error table is loaded at every boot; QLD no longer stops at its second load of the network code; SI:LOAD-MCR-FILE writes a partial last block; the undefined-host fallback of the cold-load pathnames works.

NEW

  • The site defines seven Lisp Machines, LISPM-1 to LISPM-7, at Chaos 177201 to 177207, so up to seven machines run with no site files to edit.
  • Around the system: tools/lispm-check checks a Lisp change on a saved band in seconds; tools/release-scan and tools/release-sums check what a release publishes.

KNOWN FAULTS

Not fixed, and all MIT’s: a date printed MM/DD parses as DD/MM outside the United States; (%div 0 0) returns 0; the greatest common divisor of 290 and −231 comes out negative, as on System 1001; the boot PROM’s PAGE-0-PARITY-FIX touches one word past page 0.

UPGRADING FROM SYSTEM 1001

Nothing carries over between bands: take the new pack, and serve the new sources with ozd at --file-dates utc, its default, from ozd 52eb6b0 on. A site file that gave :TIMEZONE a number now gets that fixed offset all year; name a tzdata zone for summer time.

04 / RELEASE · THE CADR

System 1001

2026-09-23 · tag release-1001 · get it

A deep cleanup of System 1000, and the faults found while making it. What will never be used is gone, not commented out, and git keeps the history.

REMOVED

38 fewer source files and about 21,000 fewer lines.

  • Machines other than the CADR: all of the Lambda and the Explorer, their processor tests, their NuBus and SDU code, their Ethernet and its microcode, and the 28 instruction declarations the CADR’s microcode never implemented.
  • Hosts it does not talk to: ITS, TOPS-20, Tenex, Twenex, VMS and Multics pathnames and hosts, and LMFILE. What remains is UNIX, the local file system, and logical hosts.
  • Hardware nobody here has: the Xerox Press and Dover printing path with EFTP, the XGP printer, the keyboard and PROM firmware tools, the wire-wrap board tester and the Votrax speech demos.
  • Patches. This system makes releases, never patches, so the machinery that loaded and wrote them is gone, with the editor’s commands for it. The version the herald prints is kept, and so is the patch directory it lives in.
  • Other dialects: MacLisp and NIL conditionals, STATUS and SSTATUS, and the compatibility macros; about 400 reader conditionals resolved to what a CADR reads, with no change to the code the reader produces.
  • Dead weight: files no system loaded, disabled blocks, duplicate copies, obsolete names nothing called, and notes that described a machine that is not here.

FIXED

  • The last of MIT’s own unfinished notes are answered.
  • The error handler saves and restores a stack group’s property list again, and returns to single-instruction stepping from a foothold.
  • A property of a function spec that is not a symbol, such as which file a method came from, can be read back again.
  • Over TELNET: ~% sends CR LF, a session whose first input is Return no longer breaks, a line read no longer traps, and a question answered wrongly asks again instead of failing.
  • The who-line shows what a running process is doing, not NIL.
  • The microcode assembler writes the diagnostic microcode files correctly.

NEW

  • A cold load can be driven without a console. It asks the file server for SYS: SITE; COLDRUN LISP and evaluates what it finds, so a build can hand it (SI:QLD) and the save with no screen. It reports its progress with MINI’s new opcode 204, which ozd 26927a8 or later writes to its log.

UPGRADING FROM SYSTEM 1000

Nothing carries over between bands: take the new pack. The 28 unimplemented instruction declarations are gone, freeing octal 732-737, 761-767 and 1100-1116, and MINI has opcode 204. The microcode is unchanged, 323.

05 / RELEASE · THE CADR

System 1000

2026-09-23 · tag release-1000 · get it

System 100 fixed and cleaned up: the same sources and microcode 323, the faults that stopped it rebuilding itself repaired, the material that is not MIT’s left out. It continues where System 100 left off.

WHAT CHANGED

  • It rebuilds itself. The fault that stopped a cold load in silence and MINI’s two stream faults are fixed. The band is compiled by the system itself, and the microcode is assembled from its sources.
  • The network: the routing table covers every subnet, and MINI finds its file server by itself.
  • Fixes from LM-3’s later work. LM-3 went on from System 100 to releases 300 through 304. Those are not taken whole, because much of them is LMI and System 130 material; instead 36 of LM-3’s bug fixes are taken one at a time, each read against this tree before it was applied: in the cold-load builder, the compiler, pathnames and the file client, Chaosnet, the window system and ZWEI. docs/upstream-changes.md records every ruling.
  • About forty faults are fixed across the tree.
  • Gone: the tape, LMFILE and Xerox printing systems. Only System is patchable, and what is not MIT’s, or not wanted, was never imported.
  • The site is named MIT, as System 100 has it, so the herald says "MIT System". Only the name is taken: the hosts are this site’s own, numbered from the subnet’s first address, OZ at 177200 and LISPM-1 at 177201 on subnet 376.

06 / RUNNING A RELEASE

Running a release.

muir-sim’s fetch scripts do the first steps for you: tools/fetch-system-for-quux.sh fetches QUUX’s current release, tools/fetch-dev-system-for-quux.sh the system in development, and tools/fetch-system-for-cadr.sh the CADR’s current release, each checked against its SHA-256 sums. By hand, QUUX’s release N with muir-sim’s quux needs no file server: its SYS: is on the machine’s file device, so its host folder holds sys/ and site/ from the sources and a home for the login.

gunzip release-N-disk.vhd.gz
tar -xzf release-N-sys.tar.gz
mkdir -p root/home/lispm
cp -a release-N/sys release-N/site root/

quux --micro --disk-pack release-N-disk.vhd --file-root $PWD/root

The machine boots to "MIT System, band 1 of LISPM-1". quux serves the screen, keyboard and mouse over RFB, for any VNC viewer. Log in with (login "LISPM" "HOST" t).

A CADR band expects its site’s Chaosnet: subnet 376, with its file, time and host table server OZ at 177200, which ozd provides, and the machine LISPM-1 at 177201. For the CADR’s release N, with muir-sim’s cadr:

gunzip release-N-pack.img.gz
tar -xzf release-N-sys.tar.gz
mkdir lispm

ozd --address 177200 --name OZ,system=UNIX \
    --root sys=$PWD/release-N/sys --root site=$PWD/release-N/site \
    --root lispm=$PWD/lispm \
    --host 177201,LISPM-1,system=LISPM --peer 177201@127.0.0.1:42043 \
    --tcp 127.0.0.1:2323,TELNET@177201

cadr --micro --disk-pack release-N-pack.img \
    --chaos-address 177201 --chaos-udp 42043 \
    --chaos-udp-peer 177200@127.0.0.1:42042 --chaos-udp-default-peer 127.0.0.1:42042

The machine boots to "MIT System, band 1 of LISPM-1". muir-sim serves the screen, keyboard and mouse over RFB, for any VNC viewer, and telnet 127.0.0.1 2323 reaches its Lisp Listener through ozd. Log in with (login "LISPM" "OZ" t) before touching files.

ozd serves a file’s dates in UTC by default, as System 1002 and later read them. Systems 1000 and 1001 write a file’s dates in their site’s zone, one hour east of Greenwich, with MIT’s daylight saving on top: for them, add --file-dates mit --timezone -1 to ozd’s command.
