01 / CADR’S RELEASES

What they
changed.

System 100 is LM-3’s bring-up of MIT’s release 99.32, with microcode 323, and the CADR’s releases, Systems 1xxx, start from it. These are the features that changed; the number after each is the release.

Removed

  • The patch system: a release is replaced by the next one. 1000 kept only System patchable; 1001 removed the rest, LOAD-PATCHES and the editor’s patch commands among it.
  • Numbered file versions; the file server has none. (1000)
  • The tape systems, since no target machine has a tape drive. (1000)
  • The LMFILE file computer and Distribution. (1000)
  • Xerox Dover/Press printing (1000), and XGP hardcopy (1001).
  • MIT’s site files, since each site supplies its own. (1000)
  • The PDP-10 MINI server, whose work ozd does. (1000)
  • Lambda and Explorer support, and the Ethernet code with EFTP. (1001)
  • File hosts other than UNIX (the ozd file server) and LISPM: Multics, VMS, TOPS-20, Tenex and ITS. (1001)
  • Code for other Lisp dialects: MacLisp, NIL and Multics, and STATUS and SSTATUS. (1001)
  • The keyboard and PROM firmware tools, and the demos that drove hardware: the Votrax speech synthesizer, the wire-wrap board tester. (1001)
  • The US-only summer-time functions. (1002)

Added

  • An example site in site/, with its hosts OZ and LISPM-n on Chaos subnet 376. (1000) The site defines LISPM-1 to LISPM-7. (1002)
  • A cold load that runs without a console, from the site’s COLDRUN script. (1001)
  • tzdata zone names in the site’s :TIMEZONE, 598 names. (1002)
  • Main memory of up to 60 boards, 3840K; the herald says how to give the system more memory. (1003)

Changed

  • System numbers start at 1000, and versions print as whole numbers. (1000)
  • The host table is a site file, SYS: SITE; HOSTS. (1000)
  • A number in :TIMEZONE is a fixed offset with no summer time. MIT applied the US rule of 1967 to 1986 to any number. (1002)
  • FILE dates on the wire are UTC, and need ozd’s --file-dates utc, its default. (1002)

Built and released

  • The system rebuilds itself from source: compile, cold load, boot, load, save a band. The microcode is assembled from its sources. (1000)
  • The tree holds sources, not generated output; the only binaries left are the fonts and two files nothing here can remake. (1000)
  • Every change to a source file carries a comment in that file saying why. (1000)
