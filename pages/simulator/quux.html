03

QUUX’s system.

tools/fetch-system-for-quux.sh

QUUX is the CADR evolved, and quux runs it, with its own boot PROM, the video controller and block-disk. It needs muir-sys’s updated microcode and system on a raw image or a VHD with a GPT partition table: MIT’s own will not run on it. The script fetches QUUX’s current release (the release notes), and checks every file against its SHA-256 sum. It puts the machine’s disk in vendor/run/ and makes the machine’s host folder beside it: QUUX reads its files from there through a device of its own, so it needs no file server.

04

Run it.

target/release/quux --micro --disk-pack vendor/run/release-2001-disk.vhd \
    --file-root vendor/run/release-2001-root

quux on the fast engine, micro; without --micro it runs rtl, at the machine’s own speed. On the rtl engine its cache and main memory are timed as an FPGA board’s. It prints where its screen is: point any VNC viewer there. It boots to a Lisp Listener; (login "LISPM" "HOST" t) logs in.

02 / ITS OWN FLAGS

What quux
alone takes.

cadr refuses each of these. The manual gives the whole of each.

FlagWhat it gives
--disk-pack <image>Its disk, block-disk’s: a raw image or a VHD, with a GPT partition table. QUUX’s disk needs no tool of muir-sim’s: it is made with standard tools.
--file-root [<name>=]<folder>[,ro]The host folders its file device serves under the pathname host HOST.
--main-memory-size <n>MWMain memory, in whole megawords, 1MW to 64MW; 32MW by default.
--cache <words>The memory cache’s size, a power of two, on rtl.
--memory-timing <read>,<write>Main memory’s timing on the memory port, in ns, or arty or de25 for a board’s own figures, on rtl.
--video-size <width>x<height>The screen’s size, at most 1920 by 1080.
--rtc <unix-seconds>|hostThe real-time clock: the host’s clock, or a start that counts the machine’s own time.
--prom <file>The boot PROM to run.
